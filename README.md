# 좌판 경도 조절 시스템 - 실험/파일럿 인프라

본 시스템 개발 전, 파라미터 실측 및 매뉴얼 모드 하드웨어 UX를 검증하기 위한 파일럿 펌웨어 모음.

## 구성

```
firmware/experiment/experiment.ino       [파일럿 1] 모터/센서 실험값 측정용 (NUM_SECTORS 기반, 최소구성 1섹터)
firmware/manual_pilot/manual_pilot.ino   [파일럿 2] 매뉴얼 모드 하드웨어(엔코더+포켓선택) 검증용 (NUM_SECTORS=2)
firmware/pilot3/pilot3.ino               [파일럿 3] 능동형/실시간/매뉴얼 통합 UI + 실제 하드웨어 제어 (4포켓/2모터 통합 하드웨어)
firmware/io_switch_test/io_switch_test.ino  파일럿3 UI를 밸브 없이(LCD+IO익스팬더+엔코더만) 검증하던 개발용 사본 (pilot3에 통합 완료, 참고용으로 보관)
firmware/lcd_test/lcd_test.ino           LCD 표시/폰트 확인용 진단 스케치
firmware/i2c_scanner/i2c_scanner.ino     I2C 주소 스캐너 (신규 장치 배선 시 주소 확인용)
server/bridge.py                         시리얼<->웹소켓 중계 + CSV 로깅 + 대시보드 정적 서빙 (파일럿 1용)
server/requirements.txt                  파이썬 의존성
web/index.html                           실시간 대시보드 (파일럿 1용)
```

개발 중에는 파일명/폴더명을 고정해서 사용 (아두이노 컴파일, 대시보드 기본 URL 등이 파일명에 의존하기 때문). 사용자가 체크포인트를 요청하는 시점에 `YYYYMMDD_HHMM` 이름의 상위 폴더로 firmware/server/web 전체를 복사해 보관 (내부 파일명은 그대로 유지).

## 파일럿 1: 모터/센서 실험 (`firmware/experiment`)

## 최소 배선 (1펌프 + 1밸브 + 1센서 + 가변저항 + 부저)

- 밸브(8채널 5V 릴레이 모듈 SZH-RLBG-009의 IN) → Arduino D2
- 펌프 (L9110S 경유) → Arduino D9 (A입력), D10 (B입력)
- 압력센서 아날로그 출력 → Arduino A0
- 가변저항(WH148) 가운데 단자 → Arduino A1 (펌프 속도 조절용)
- 부저 → Arduino D4

섹터를 늘릴 때는 `experiment.ino`의 `NUM_SECTORS`, `VALVE_PINS[]`, `SENSOR_PINS[]`, `alarmRawThreshold[]`만 확장하면 됨 (하드코딩 없음).

**릴레이 배선/극성 (SZH-RLBG-009, 2026-07-10 최종 확정)**: 밸브(+)는 릴레이 **NO** 단자에, 공급전원(+)은 **COM**에 연결. 릴레이는 **액티브하이**(IN=5V일 때 에너자이즈되어 COM-NO 연결/밸브 통전, IN=0V/GND일 때 비활성으로 COM-NC 연결/밸브 비통전 — 판매처 디바이스마트 확인). `setValve()`: state=1(열림/통전)일 때 **HIGH**, state=0(닫힘/비통전)일 때 **LOW** 출력, 부팅 기본값 LOW(안전).

(이 결선/극성은 디버깅 중 여러 번 정정을 거쳤음 — 배선 바꾸실 때는 반드시 이 문단 기준으로 맞춰볼 것.)

**펌프 속도 제어**: 가변저항이 PWM 듀티(0~255)를 직접 결정. 소프트웨어(대시보드)는 방향(정/역방향)만 지정. 대시보드는 현재 속도를 0~100%로 표시.

**경보 부저**: 섹터 raw 값이 임계값(`alarmRawThreshold`) 이상이면 즉시 440Hz 비프음 발생 (노이즈 필터링 없이 즉시 반응), 아래로 내려가면 즉시 정지. 기본값은 ADC 풀스케일(1023)을 40kPa로 임시 가정한 것이라, raw→kPa 변환식이 실측되기 전까지는 실제 40kPa 지점과 다를 수 있음 — `ALARM,<sector_idx>,<raw>` 명령으로 실시간 조정.

## 실행 방법

1. **랩탑에서 펌웨어 업로드** (arduino-cli)
   ```
   arduino-cli compile --fqbn arduino:avr:uno firmware/experiment
   arduino-cli upload -p COM3 --fqbn arduino:avr:uno firmware/experiment
   ```

2. **파이썬 서버 실행** (랩탑, 아두이노 USB 연결된 상태)
   ```
   cd server
   pip install -r requirements.txt
   python bridge.py --port COM3
   ```
   포트를 생략하면 자동 탐색 시도.

3. **브라우저에서 대시보드 접속**
   ```
   http://localhost:8000/
   ```
   (CSV 다운로드 버튼이 상대경로이므로 file://로 직접 열지 말고 위 주소로 접속할 것)

## 시리얼 프로토콜

- Arduino → PC: `T,<millis>,<sector0_raw>,<sector1_raw>,...` (50ms 주기, raw = analogRead 0~1023)
- Arduino → PC: `M,<pump_speed 0-255>,<pump_dir 0|1>` (50ms 주기, 가변저항으로 결정된 현재 펌프 속도)
- Arduino → PC: `READY,<NUM_SECTORS>` (부팅 시 / STATUS 요청 시)
- PC → Arduino: `VALVE,<sector_idx>,<0|1>` (0=닫힘, 1=열림)
- PC → Arduino: `PUMP,<dir 0|1>` (속도는 가변저항이 결정, 소프트웨어는 방향만 지정)
- PC → Arduino: `ALARM,<sector_idx>,<raw_threshold>` (경보 raw 임계값 조정)
- PC → Arduino: `STATUS`

## 로그

`server/logs/log_<타임스탬프>.csv` 로 매 실행마다 새 파일 생성. 대시보드의 "CSV 다운로드"는 현재 실행 중인 로그 파일을 받아옴.

## 실측 결과 (2026-07-13 확정)

- **펌프 실제 회전 방향**: 현재 방향(dir=0)이 맞음. 확정.
- **목표 압력 상한**: raw≈500 (1차 확정, ADC raw 기준). `alarmRawThreshold`/`alarmMaxRawThreshold` 기본값에 반영함.
- **압력센서 노이즈**: 개별 편차는 정밀 측정 안 했지만 잠정적으로 **±5(raw)** 허용폭으로 가결.
- **밸브 개폐 시 자연 배기 속도**: 충분히 빠름을 확인.
- **raw→kPa 변환식**: 40kPa까지 쓸 일이 없다고 판단되어 **보류** (raw 기준으로만 운용).

## 파일럿 2: 매뉴얼 모드 하드웨어 검증 (`firmware/manual_pilot`)

가변저항 1개 + 서브스위치로 4포켓을 선택/조절하면 전환 시 "포인트/밸류 점프"가 발생하는 설계상 결함을 발견하여, 엔코더(EC11, 상대회전값) 기반으로 대체한 것을 검증하는 파일럿. 대시보드 없이 하드웨어 단독으로 동작 (Serial Monitor로 임계값 튜닝만 가능).

### 배선 (2포켓 축소 구성)

- 엔코더(EC11 계열, 5핀: GND/S1/S2/KEY/5V, 20PPR) S1 → D2 (인터럽트, CLK 역할), S2 → D3 (DT 역할), KEY → D5 (SW 역할) — 2026-07-14 실측 결과 방향이 반대라 `encoderISR()` 코드에서 이미 반전 처리함 (배선은 그대로, S1↔S2 재배선 불필요)
- 엔코더 디바운스 `ENCODER_DEBOUNCE_US=5000`(5ms)로 상향 — 펌프 PWM 노이즈로 인한 오인식 방지 (2026-07-14)
- 부저 → D4
- 밸브 0/1 (8채널 5V 릴레이 모듈 SZH-RLBG-009의 IN) → D6 / D7
- LED 0/1 (포켓 인디케이터) → D8 / D11
- 펌프 (L9110S) → D9 (A입력), D10 (B입력, 고정 방향만 사용 — `PUMP_FIXED_DIR=0`, 파일럿1 실측으로 확정됨)
- 압력센서 0/1 → A0 / A1

**펌프 속도**: 포텐셔미터 제거, 항상 최대속도(`PUMP_FULL_SPEED=255`)로 작동 (2026-07-14 확정, 파일럿1과 다름 — 파일럿1은 계속 포텐셔미터로 속도 조절).

**릴레이 배선/극성**: 파일럿 1과 동일한 SZH-RLBG-009. 밸브 전원은 릴레이 **NO** 단자에, 공급전원(+)은 **COM**에 연결. `setValve()`: state=1(열림)→**LOW**, state=0(닫힘)→**HIGH** (2026-07-13 확정). 부팅 기본값 HIGH(닫힘/안전).

**⚠️ 공용 펌프 배관 누설 (2026-07-14 발견)**: 밸브 "닫힘" 상태는 대기가 아니라 공용 펌프 배관에 연결되는 것이라, 선택 안 된 포켓 밸브도 기본이 닫힘(펌프측)이면 부풀릴 때 그 배관을 타고 다른 포켓까지 같이 부풀고, 배기 후 재차 닫히면 역류도 발생함. 체크밸브는 역류만 막지 정방향 동시유입은 못 막아서 기각.

**시도했다가 되돌린 것 (2026-07-14)**: 3way 셀렉터밸브(D12)를 공용배관과 각 포켓 밸브 사이에 추가해봤으나, 배선 중 원인불명 오작동(부팅 시 LED 자동점등, 엔코더 회전 시 모터 제멋대로 작동, 부저 굉음)이 발생. 디버깅 결과 **아두이노-엔코더 간 공통 그라운드 미연결 + 엔코더 5V 핀을 별도 파워서플라이에 연결한 것**이 원인으로 추정되나 완전히 해결 못 하고 코드만 셀렉터밸브 추가 이전 상태로 되돌림(체크포인트 `20260716_0824`). 배선을 처음부터 다시 구성할 예정.

**현재 검토 중인 대안**: 포켓별 밸브를 전부 **2way(개통/차단) 밸브**로 교체해서 물리적으로 격리하는 방향. 검토 중인 제품: FS PUMP사 **0520D(6V)**. 배기는 셀렉터/3way 없이 펌프 역회전으로 처리하는 방식과 함께 검토 (아래 "실측 결과" 표 참고).

### 동작 시나리오

1. 엔코더 스위치 롱프레스(≥`LONG_PRESS_MS`=1000ms) → 매뉴얼 모드 진입, 0번 포켓 선택 + LED0 점등
2. CW로 돌리는 동안(연속 회전, `HOLD_TIMEOUT_MS`=200ms 이내) → 선택 포켓 밸브 닫힘(펌프측 연결) + 펌프 최대속도 작동
3. 최대압력 도달 → 펌프 정지 + 440Hz 비프
4. CCW로 돌리는 동안에만 → 선택 포켓 밸브 열림(배기), 회전 멈추면 즉시 밸브 잠김
5. 최저압력 도달 → 밸브 강제 잠금 + 440Hz 비프 (CW의 최대압력 도달과 대칭 처리)
6. 스위치 숏프레스 → 다음 포켓으로 전환 (이전 포켓 밸브/펌프는 안전하게 정지 후 전환)

CW/CCW 모두 "돌리는 동안에만" 동작하는 홀드 방식으로 통일 (원 시나리오는 CCW만 명시했으나 대칭성/안전성을 위해 CW도 동일하게 적용 — 사용자 확인됨).

### 시리얼 명령 (튜닝용)

- `MAXTH,<idx>,<raw>` — 포켓별 최대압력 raw 임계값 조정 (기본값 500 = 파일럿1 실측 확정치)
- `MINTH,<idx>,<raw>` — 포켓별 최저압력 raw 임계값 조정 (기본값 0 = 아직 미확정)

### 아직 미확정

- `alarmMinRawThreshold`(최저압력 하한) 실제 값 — 안전 하한 실측 필요

## 통합 하드웨어 (파일럿3 ~ 최종 통합 공용)

파일럿1/2처럼 최소구성을 따로 만들지 않고, **4포켓/2모터 최종 규모 하드웨어로 바로 직행**하기로 결정함. 이 배선/핀맵은 파일럿3(능동형) 전용이 아니라 **파일럿4(실시간)·매뉴얼 모드·최종 통합까지 그대로 이어서 쓸 최종 하드웨어 기준**이며, 앞으로 바뀌는 건 펌웨어(코드) 쪽이지 배선이 아님. 밸브(6채널)/LED(3)/스위치(3)는 아두이노 핀 부족으로 PCF8574 확장모듈 2개를 경유, LCD도 PCF8574 인터페이스 내장 I2C 1602 모듈 사용. 전부 같은 I2C 버스(A4/A5)에 병렬 연결.

### 핀맵

**아두이노 직결**

| 핀 | 용도 | 비고 |
|---|---|---|
| D2 | 엔코더 CLK | 인터럽트. 파일럿3에선 미사용, **매뉴얼 모드 회전 조작용으로 예약** |
| D3 | 엔코더 DT | 파일럿3에선 미사용, 매뉴얼 모드 회전 조작용으로 예약 |
| D4 | 엔코더 SW | 롱프레스=시스템 전원 ON/OFF (모든 모드 공용) |
| D5 | 모터2(그룹2, 포켓2/3) IN1 | PWM(Timer0) |
| D6 | 모터2 IN2 | PWM(Timer0) |
| D7 | 부저 | tone() |
| D9 | 모터1(그룹1, 포켓0/1) IN1 | PWM(Timer1) |
| D10 | 모터1 IN2 | PWM(Timer1) |
| A0~A3 | 공압센서 0~3 | analogRead |
| A4/A5 | I2C SDA/SCL | LCD+IO확장+밸브확장 공유 |
| D8,D11,D12,D13 | 여유 | 미사용 |

엔코더는 GND/S1(CLK)/S2(DT)/KEY(SW)/5V **전부 모듈 매뉴얼대로 정상 배선** (5V 핀 연결 해제 등 별도 우회 조치 불필요 — 2026-07-21 확정).

**I2C 장치**

| 주소 | 장치 | 용도 |
|---|---|---|
| 0x27 | LCD(1602, PCF8574 내장) | 상태/포켓 레벨 표시 (모든 모드 공용) |
| 0x24 | PCF8574 (IO 익스팬더) | LED 3개(P0~P2, 프리셋 인디케이터) + 스위치 3개(P3~P5, 프리셋 1/2/3 불러오기) |
| 0x20 | PCF8574 (밸브 익스팬더) | 3way그룹1(P0), 2way포켓0(P1), 2way포켓1(P2), 3way그룹2(P3), 2way포켓2(P4), 2way포켓3(P5) |

그룹 매핑: 그룹1 = 포켓0,1(모터1) / 그룹2 = 포켓2,3(모터2). 그룹당 3way 1개(공용라인↔펌프/대기 전환) + 2way 2개(포켓별 격리).

### 실측 전 확인 필요 (가정 상태, `pilot3.ino` 상단 주석 참고)

- 밸브 익스팬더 출력 극성(`VALVE_ACTIVE_HIGH=true` 가정: 1=에너자이즈)
- LED 익스팬더 출력 극성 — **2026-07-21 실측 확정: `LED_ACTIVE_LOW=false`(1=켜짐)**. PCF8574 핀→저항→LED→GND 배선이라 HIGH(약한 풀업, ~100µA)로만 켜져서 밝기가 약함. active-low로 재배선(VCC→저항→LED→핀, LOW의 강한 싱크 ~25mA 활용)하면 밝아지지만, 실제 재배선은 보류함.
- LCD 백팩 핀 배치(P0~P7=RS/RW/EN/BL/D4~D7, 시중 통용 배치 가정)
- 펌프 방향(`PUMP_FIXED_DIR=0`, 파일럿1 실측치를 두 모터에 동일 적용 가정, 개별 검증 필요)

**PCF8574 주소 실측 결과 (2026-07-21, `firmware/i2c_scanner`로 확인)**: 두 모듈 다 공장 기본값(주소 점퍼 3행 모두 2-3열 브릿지)이 0x20이라 그대로 두면 충돌함. 점퍼 1개 행을 2-3열→1-2열로 옮긴 모듈이 **0x24**로 확정 (처음 예상했던 0x21이 아님 — 점퍼 조작 결과는 보드마다 다르므로 이런 식으로 스캐너로 실측 후 코드에 반영할 것). 점퍼를 그냥 빼기만 하면 핀이 붕 떠서(floating) 값이 불안정하니, 반드시 반대쪽 열(1-2열)로 옮겨 꽂을 것.

**IO/밸브 배정 재확인 (2026-07-23)**: 처음엔 "기본값 0x20=IO, 점퍼조정 0x24=밸브"로 가정했으나, 실제 배선을 켜보니 **LED/스위치가 물린 모듈이 0x24, 밸브용이 0x20**으로 반대였음(펌웨어 코드만 주소 스왑해서 해결, 배선 변경 없음). 즉 어느 모듈이 어느 주소가 될지는 점퍼 조작 순서가 아니라 실제 어느 모듈에 어느 배선을 했는지에 달려있으니, 매번 LED/스위치 반응으로 직접 확인할 것.

### 실장 전 배선 체크리스트 (2026-07-24 확정)

**릴레이 COM/NO/NC 배선**: `COM ← 공급전원(+)`, `NO → 밸브(+)`, `밸브(-) → 공급전원 GND(릴레이 안 거치고 직결)`. COM/NO/NC 구분이 헷갈리면 멀티미터 도통모드로 확인 (비여자화 시 COM-NC 도통, 여자화 시 COM-NO 도통 — 릴레이 자체 LED 점등 = 여자화 상태).

**플라이백 다이오드 — 밸브마다 개별 필수**: 2way 밸브 4개 전부, 각자 자기 코일 양단(밸브 자신의 +/- 리드, 로직 신호선 아님)에 **개별로** 1N4007 다이오드 병렬 연결 (캐소드→밸브+, 애노드→밸브-). 릴레이 보드에 이미 박혀있는 다이오드는 **릴레이 자신의 코일**을 보호하는 것뿐이라 이거로는 밸브 보호가 전혀 안 됨 — 반드시 밸브 쪽에 별도로 달아야 함. 릴레이 접점이 열리는 순간 코일 에너지가 빠질 경로는 그 코일 바로 양단에만 있어야 해서, 공용 전원단에 하나만 달아 여러 밸브가 공유하는 방식은 효과 없음 (실측 확인됨).
- 모터(펌프) 쪽: 다이오드 없어도 무방 (실측상 오작동과 무관했음)
- 3way 밸브: 다이오드 없어도 무방 (2way처럼 압력에 맞서 닫히는 구조가 아니라서 필요성 낮음, 다만 달아도 무해)
- 증상: 압력이 어느 정도 걸린 상태에서 밸브가 닫힐 때(엔코더 릴리즈 등) 릴레이가 빠르게 딱딱거리며 오작동 — 압력에 맞서 닫히며 기계적으로 미세 바운스가 생겨 코일이 반복적으로 역기전력 스파이크를 내는 것으로 추정.

**공통 그라운드**: 아두이노, PCF8574 2개, LCD, 릴레이 모듈(로직측 GND + JD-VCC측 GND 둘 다), 모터드라이버, 센서 — 전부 하나의 공통 그라운드 지점(스타 그라운드)에 모을 것. 로직 전원(5V, 아두이노에서)과 구동 전원(모터/밸브 외부전원)은 (+)만 분리하고 GND는 공통으로 묶음.

## 파일럿 3: 통합 UI + 하드웨어 제어 (`firmware/pilot3`)

능동형(AUTO FIT)/실시간(REALTIME)/매뉴얼(MANUAL) 3모드 UI(모드선택/캘리브레이션 연출/자세보정/포켓조절/프리셋 저장·불러오기)를 `firmware/io_switch_test`로 하드웨어 없이 먼저 검증한 뒤, 실제 밸브/펌프/센서 제어를 연결한 최종 통합본. 2way 밸브 도착 후 바로 하드웨어 검증 가능한 상태.

- **모드1(AUTO FIT)**: 엔코더로 진입 → 짧게클릭 시 실제 능동형 알고리즘(**RESET→INFLATE→SWEEP→RETURN→LOCKED**) 구동, LCD 연출은 그 진행상황에 맞춰 표시. RESET 단계(2026-07-28 추가)는 현재 압력 상태와 무관하게 먼저 4포켓 전부 배기해서 항상 같은 기준(빈 상태)에서 INFLATE를 시작하도록 하는 초기화 단계 — 3way 대기모드+2way 전부 열기, 센서값이 `resetTargetRaw`(기본 90raw, 시리얼 `RESETRAW,<raw>`로 조정) 이하로 내려가거나 10초 타임아웃되면 INFLATE로 전환
- **모드2(REALTIME)**: 진입 시 밸브 잠금 + 그 시점 4포켓 raw값을 기준압으로 저장. 이후 200ms 주기로 실측하여 어느 포켓이든 기준압 대비 `postureThreshold`(기본 40 raw, 시리얼 `POSTURE,<raw>`로 조정, 2026-07-28 중 40→82→60→40으로 여러 번 재조정) 이상 벗어난 상태가 `postureConfirmMs`(기본 2000ms, 시리얼 `POSTURECONFIRM,<ms>`, 순간적으로 스치는 변화는 무시하고 지속될 때만 인식하도록 2026-07-29 추가)만큼 지속되면 자세이상 감지 → alert. 복귀 판정도 실측 기반(최소 1초 유지 후 다시 기준압 이내로 들어오면 복귀, 10초 넘도록 못 돌아오면 안전상 강제 종료). 단, 자세를 교정해주는 보정 액추에이션(밸브 재조정)은 아직 없음 — 지금은 감지+알림(백라이트 점멸/부저)까지만 구현 (실제 보정 동작은 모드4에서 프로토타입 검증 중)
- **모드4(RT-ACTIVE, 2026-07-29 추가, 실시간 능동보정 프로토타입)**: 감지 로직 자체는 모드2와 동일(기준압 저장 + `postureThreshold`/`postureConfirmMs` 재사용, 모드2·4는 동시에 안 돌므로 상태 공유). 자세이상이 확정되면 비프+LCD 알림(`mode4AlertShowMs` 기본 2000ms, 시리얼 `MODE4ALERT,<ms>`) 표시 후, **기준압 대비 압력이 오른(하중이 더 실린) 포켓들만** 골라서 `pressureCeilingRaw`(500raw)까지 채움(BOOSTING) → 다 채우면 `mode4HoldMs`(기본 3000ms, 시리얼 `MODE4HOLD,<ms>`) 대기(HOLD) → 원래 기준압으로 전체 복귀(RETURNING, `startTargetSeek`/`tickTargetSeek` 재사용) → 도미솔도 완료음 + 재무장(새 기준압 다시 캡처). 더블클릭으로 어느 하위단계에서든 안전정지 후 모드선택으로 복귀 가능
- **모드3(MANUAL)**: 포켓 선택 후 회전으로 실제 밸브/펌프 조절 — 파일럿2와 동일한 홀드 방식(CW를 계속 돌리는 동안만 부풀리기, CCW를 계속 돌리는 동안만 배기, `ADJUST_HOLD_TIMEOUT_MS`=250ms 안에 새 스텝 없으면 즉시 정지, 2026-07-28 200→250ms로 조정) + 파일럿2의 "첫 펄스 확인" 디바운스(단발성 회전 신호는 pending으로만 기록, 같은 방향 신호가 유효시간 내 한 번 더 들어오거나 이미 홀드 중일 때만 실제 반영) + 밸브/펌프 상태가 실제로 바뀔 때만 I2C 씀(불필요한 반복 통신으로 인한 릴레이 채터링 완화). 프리셋 저장/불러오기도 실제 센서값 기반 + EEPROM 저장. 프리셋 불러오기는 능동형 모드의 RETURN 단계와 같은 목표추적 로직(`startTargetSeek`/`tickTargetSeek`)을 재사용해서 4포켓을 동시에 목표치로 수렴시킴
- 프리셋 택트스위치 3개는 어느 화면에서든 즉시 동작(단, 능동형 모드가 실제로 하드웨어 움직이는 중이면 충돌 방지를 위해 무시). **프리셋 적용 중 다른 입력(클릭/다른 프리셋)이 들어오면 즉시 중단**하고 이 프리셋을 누르기 직전의 압력 상태로 안전하게 되돌아간 뒤(`presetPreviousRaw[]`, `abortPresetApplying()`) 모드선택으로 이동함(2026-07-30, 예전엔 적용 완료까지 다른 입력을 무시했음)
- **프리셋 적용 완료 후 화면 고정 (2026-07-30)**: 정상적으로 적용이 끝나면 "PRESET #N/값들" 화면에 그대로 멈춰있고(`presetFrozen`), 사용자가 아무 버튼이나 눌러야 모드선택으로 이동함 — 예전엔 1.5초 뒤 자동으로 이전에 하던 모드로 돌아가버려서, 예를 들어 모드1 중 프리셋을 적용하면 끝나자마자 다시 캘리브레이션이 시작되는 문제가 있었음
- **프리셋 기본값 시딩 (2026-07-28)**: EEPROM이 처음(시딩 마커 없음)이면 프리셋 1=`0,0,10,10`(포켓1,2 완전배기/포켓3,4 레벨10), 2=`2,2,2,2`, 3=`10,10,10,10`을 자동으로 한 번만 심어둠(`seedDefaultPresetsIfNeeded()`). 이후엔 사용자가 북마크로 저장한 값이 계속 유지되고 재시딩되지 않음. 레벨 `0`은 프리셋 전용 특수값으로 "완전배기(대기압 근처)"를 의미(`levelToRawTarget(0)`→80raw), 일반 레벨(1~10)과 별개로 처리됨
- 능동형 모드는 INFLATE/SWEEP/RETURN 각 단계 종료 시 소요시간을 시리얼로 출력(`INFLATE 종료: Xms (ceiling 도달/timeout)` 등) — 고정 타이머가 아니라 실측 센서값(ceiling/floor/tolerance)에 의해 종료되며, 매번 소요시간이 비슷하게 나오는 건 물리적 과정 자체가 반복성이 있기 때문일 가능성이 높음. 실제로 timeout에 걸리는지 vs 센서값 도달로 끝나는지는 이 로그로 구분 가능
- **모드5(STRETCHING, 2026-08-03 추가)**: 진입 시 현재 압력을 저장 → 4포켓 전부 배기(0)로 초기화 → **포켓1+4**를 `pressureCeilingRaw`(500raw)까지 채우고 `stretchHoldMs`(기본 3000ms, 시리얼 `STRETCHHOLD,<ms>`) 유지 후 배기(0) → **포켓2+3**을 동일하게 채우고 유지 후 배기 → 이 한 세트를 `stretchReps`(기본 10회, 시리얼 `STRETCHREPS,<n>`)만큼 반복 → 진입 시 저장해뒀던 압력으로 전체 복귀(`startTargetSeek`/`tickTargetSeek` 재사용) → 도미솔도 완료음 + "Stretching Complete" 표시. 포켓1+4, 포켓2+3은 각각 서로 다른 그룹(모터)에 걸쳐 있어서 그룹 내 다른 포켓의 2way 밸브만 잠그는 방식으로 대각선 포켓만 선택적으로 구동함. 더블클릭으로 어느 단계에서든 안전정지 후 모드선택으로 복귀 가능(단, 이 경우는 이전 압력 복귀 없이 즉시 정지 — 프리셋과 달리 별도 요청 없었음)
